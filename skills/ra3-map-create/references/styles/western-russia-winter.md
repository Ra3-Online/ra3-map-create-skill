# 俄国冬季：城区、院落、铁路与港口

## 使用范围与证据

适用于雪季的俄国城市、滨水工业区和村镇。先读用户的城市密度与历史时期要求。现实复刻的斯大林格勒应研究真实城市的关系，再用红警 3 原版资产表达；下面的战役场景是美术参考，不能当作真实历史城市测绘。

已逐分区查看原版战役来源样例 m049（Russian Village，16 分区）、m050（Kremlin，8 分区）、m051（Vladivostok，9 分区）。这些是训练目录中的战役样例副本，诊断截图保留地形与美化，隐藏部分已识别军事物体。没有把任务经济、军事基地或出生位置作为城市范式。起义补充 u012、u013、u023、u030、u031、u035、u036、u064、u065、u072 来自社区整理的官方来源挑战场景；不能把整理版称为未改动 EA 原文件。u001 北境极地、m053 哈尔科夫、m054 明斯克是社区补充，分别标注，不冒称官方。

图册用于判断整个场景的层级关系；单体入口、灯臂方向、模型接缝必须放大检查。资产 ID 由统一 Core 的观测数据核对；“出现在地图中”不等于“已认证任何位置都能用”。完整候选查询 [observed-assets.json](../observed-assets.json)，缺目录项与未验证模型先做样板。

## 一级：城市；二级：住宅与商业街块

观察：m050 的主要道路形成街块，河岸道路随堤岸少量转折；广场、住宅、围墙主景区承担不同功能。m049 的密集街块主要位于低处沿岸，树林与木屋更常见于起伏地；不是把整个场景铺成等距房屋阵列。u036 既有完整街块，也有有路径、植被与中心主题的开敞公共空间。

执行顺序：道路与人行道 → 街块用地 → 原尺寸民房 → 入口通道 → 院落分区 → 围界 → 停车与家具。用户禁止缩放或堆叠时，房屋保持 prototypeScale = 1，相邻体量通过选型与间距解决。L 形或 U 形院落优先选择原生相应模型；不能用互相穿插的房屋模拟。

|---|---|---|---|

## 一级：城市；二级：纪念碑广场、医院、车库、公园

### 纪念碑广场

m050 近景可见主景居于开敞前场，路径形成明确到达方向，灌木围出种植区，外围道路通行。学习的是“轴线—前场—环绕路径—植被边界”，不是每张俄国图必须复制克里姆林宫的巨大围墙和建筑。

1. 先确定广场主轴，与中心道路/重要建筑入口形成关系。用户指定地图中心纪念碑时，先保障中心为可识别公共节点。
2. 用统一铺装画前场与主通道；铺装本身要有完整边界，不能靠堆物遮补破碎地表。
3. 主景只选一个匹配时期、尺度的纪念碑。`KR_Statue01` 已观测于 m049/m050；`SL_CavalryStatue_01`、`ST_PilotStatue_01`、`ST_SwordStatue_01`、`ST_MotorCycleStatue_01` 在 m049 是不同主题候选，不能全部堆到一个广场。
4. 树与座椅围绕边缘布置，保证从主要到达道路可以看到主景。少量花坛/链栏强调边界，避免让它们阻断实际通道。

### 医院与车库

这是功能化配套的推荐模板，不声称每一个模板都来自官方特定院落。

- 城市医院：临次干路，接完整铺装前场，预留驶入/停靠位置；小围界与绿地把医院和货场隔开。停车车辆不要和建筑门重叠。科技医院会影响战役规则，功能与归属需按用户任务设定。
- 城市车库/汽修：沿服务巷或交通边缘，门前硬地可驶入，少量停泊民车、维修工具与废物靠侧后方，车道保持空。
- 村镇医院：若用户允许村镇，较小公共节点接主要村路，外围可有木围栏与植被；不把城市大停车场、纪念广场、精细街具硬套到孤立小屋。没有合适小型医院外观时，说明原版资产限制，不能擅自用普通民房冒称可占领医院。
- 冬季公园：路径有入口与出口，林地与雪地留白由路径组织；裸树、针叶树与低灌木分层。雪季不满铺热带花卉或棕榈。无建筑地块依然可成为球场、公园、存车场、纪念庭园或堤岸绿地，不是无主题撒树。

## 一级：工业与港口；二级：铁路、码头、仓储

m051 近景：手指形岸线容纳货船；起重机靠水，货箱放在岸上；仓库接道路与铁路；岸边栏杆保护步行边。它们构成物资流动关系，不是“这些物体通常出现一起”的装饰名单。

| 对象 | 使用方式 | 必查项 |
|---|---|---|
| `VL_Harbor_Crane01`、`OD_PortCrane01` | 基座在平整岸上，吊臂对装卸水域或货场；m049/m051 可作为外观对照 | 不能悬空、不能把臂旋到房顶或主要车道；以真实模型吊臂方向核对角度 |
| `VL_ShippingBoat01`、`VL_TugBoat01`、`OD_TugBoat01` | 货船在深水侧平行码头，拖船在港池/入口；先检测船体与水面关系 | m051 货船实例有 groundRelativeZ = 70，不能把该数值复制到不同水位地图。以当前水面和模型浮线决定位置 |
| `VL_BoxCar01`、`VL_FlatCar01` | 货车厢沿铁轨摆放，整列方向与轨道切线一致，轨距和轮缘可见对齐 | 车厢不是铁路素材；不能连续缩放车厢当轨道，不让车厢横跨路口 |
| `VL_BustedTrainStation` | m049/m051 的破损站房候选，站台一侧接轨道，正门另一侧接站前路/广场 | 破损状态不符合完整新城市时需换合适模型；不能宣称“中央车站”但轨道远离站台 |
| `VL_SeaWall01`、`KR_RiverEdge01`、低栏杆 | 与人工堤岸分段连续，连接端点并照顾岸线转折 | 岸墙是工程边界，不把自然野岸全部砌墙；高度变化处先做地形/挡土结构 |

轨道跨路的位置必须明确：平交道口连接同一高度，留双向停车/闸杆空间；跨线桥则需要真实不同高度、桥头坡道与支撑关系。原版关卡的脚本交通状态不能自动复制。只有已验证存在且外观匹配的交通闸/信号模型才能使用，不能把链栏称为交通闸。港口船只不是每几格平均摆一只；让码头、航道、停泊位有主次与空隙。

交界处理规则：硬铺装对硬铺装或道路，边界应清楚并依附真实路缘；雪与裸地/植被等自然交界才适合局部细化。45° 斜线容易显示网格阶梯，先做短样板确认边缘工具输出；不能用“全图自动羽化”保证消除锯齿。u036 院落近景和 m056 的诊断渲染可见异常三角/棋盘边，不能学习为官方美术做法，也不能以此判定原地图本身有错。道路边缘异常需要识别是绘制数据还是当前渲染问题。

## 朝向与完成检查

主街道/街块尽量采用用户要求的 45°、135°、225°、315° 世界方向。房屋主立面与街道的关系优先于机械复制角度数字，因为模型的本地正面不同。曲线沿岸路可以缓慢转折；不因追求奇数倍方向而把河岸画成频繁锯齿。灯、闸杆、座椅和起重机各自服务对象不同，必须单独确定朝向。

完成一个街块后检查：入口通到路；门前无树、栏、车；院后功能清楚；墙有开口；停车位可进入；路灯照路；铁路与站台匹配；硬地边缘没有假羽化；不同高程通过可见斜坡/桥接连接。做两个相邻完整街块并截图通过后再扩展。
