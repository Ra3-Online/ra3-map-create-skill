# 俄国暖季城市与站区：列宁格勒、斯大林格勒、敖德萨

## 证据与适用边界

原版战役来源 m055、m056、m057、m058、m059 全图分区已实际查看；m055、m056、m057 另看院落原尺寸近景。季节按可见绿色地面归为“暖季”，不能只根据目录写成某一个月份。列宁格勒与斯大林格勒资产可跨俄国暖季城市使用，但历史复刻需要另外核查年代；原版战役自身的游乐园/军事基地不能当作真实城市模板。

## 城市 → 街块 → 房屋与院落

m055/m056/m057 的近景共同显示：车路、人行边缘、建筑底板、院落铺装、种植带各有范围。民房保持原生尺寸；正面街与后方绿地/服务区有区分。相邻建筑在高度、屋顶色、平面形状上变化，但同一街块用有限房屋族。没有必要每个地块放一栋不同国家大楼。

| 功能 | 候选对象 | 放置关系 |
|---|---|---|
| 主住宅族 | `ST_Building05`、`ST_Building02`、`ST_Building04`、`ST_Building03`、`ST_Building01`、`ST_Building06`、`ST_Apartment_01` | 相邻平行/垂直，主面向街；以原生 L/U 型配合院落，保持门前通达。m056 可见公寓与小楼混合；勿推定每个型号正面是本地 +X |
| 大公寓补充 | `OD_Apartments01`、`OD_Apartments02` | m057 和周边俄国场景使用；按街块中心/角部角色配置，不挤压所有院落 |
| 旅馆/商业节点 | `ST_Hotel_01` | m056 已观测；临主街/公共节点，前场和停泊位置宽于普通住房，入口相连 |
| 宗教与公共建筑 | `ST_Church_01`、`OD_Church01`、`OD_Courthouse` | 公共地块有到达路径和前场；周围低绿化保持可识别轮廓；无需把每个城区都加同样教堂 |
| 消防设施 | `ST_FireStation_01` | m056 已观测。车库方向接宽硬地和道路，门前留空；历史/地域匹配先看模型 |
| 仓储 | `OD_Warehouse01`、`OD_Warehouse02` | 靠铁路/港口/服务街，硬质装卸场与居民前院隔开 |

具体单体与可用性仍须由当前目录确认；表是通过 Core 数据存在性核查的候选。使用首个型号时做入口朝向与原尺寸样板。

住宅院落不要空而无主题，也不要填满：选择一块主活动硬地/中央草地，连接两三个真实入口；边缘花坛、树、少量座椅；停车位放沿服务边。m055 的商业长楼前有餐桌区域，m056 的站前有停泊场；餐饮桌不能套用到消防车库前。

## 城市 → 中央车站、铁路和纪念节点

观察 m056：`ST_BustedTrainStation` 一侧邻铁路线，另一侧是大停车前场和道路；铁轨主要沿城区边缘行进，避免贯穿每个住宅院子。站房前道路连接街块，轨道与道路在需要的位置集中交会。学习关系，不复制整张战役的轨线形状。

执行：轨道主轴 → 原尺寸站房与站台 → 站前人行广场 → 城市道路连接 → 停车/货运区 → 跨线交通。站房是破损型号，完整战前城市不能未经确认直接用；若原版仅提供该模型，向用户说明外观选择而非偷偷缩放/堆叠房屋造车站。

| 组件 | 资产与证据 | 规则 |
|---|---|---|
| 站房 | `ST_BustedTrainStation`，m056 | 站房背侧接轨，正面接站前路；旋转由真实站台/入口判断 |
| 轨道 | `VL_Rail01`，m056 #2076；真实mesh约90×22.377 | 普通Object，本地X约90端面候选；Z=0/alignToTerrain=true坡段已观察，道床与坡口另核 |
| 货运车厢 | m057 的 `OD_BoxCar01`、`OD_FlatCar01` | 与铁轨切线和轨距一致；只在货线/停靠轨，不横穿道口 |
| 起重机、港口 | m057 的 `OD_PortCrane01`、`OD_TugBoat01`、`OD_PortLighthouse01` | 起重机基座在岸上，灯塔在可见航道/入口，拖船在水域；工作场留完整空闲装卸面 |
| 纪念碑 | m056 的 `ST_GrandEmperorStatue`、`ST_RussianFought2DeathStatue`、`ST_RussianBigMamaStatue` 等 | 只选匹配主轴、年代和尺度的一件主景；不要将所有雕塑名单集中堆放；现实斯大林格勒时期需历史核对 |

轨道/站房族不等于轨道铺设命令。轨道弯曲使用目录中确实存在的配套段或编辑器验证的曲线结构；不通过车厢、围栏造假。平交道口需要同高程的轨与路、实际交通闸和信号设施，路面没有被栏杆封死。高架/桥梁需要结构与桥头斜坡，不能只把道路或站房抬 Z。

| `ST_Table03`、`CS_Bench01` | 餐饮前场和公共步道；桌椅与具体活动/入口相连 | 医院救护入口、工业货场与轨道安全区 |

路灯首先确认型号实际灯臂和光锥，灯杆在步行侧，灯头照车路；单看“朝向与道路平行”无法判断。行道树使用一个主族；公园增加低灌木、花坛、另一种树形成层次；自然野地用地表斑块+坡脚石+林缘，不能沿网格等距植树。对冬季复刻，用雪季版植物并审查暑期餐饮露台/游乐设施是否适合。

先读 [道路制作](../road-construction.md)，看 [m055桥头](../../assets/roads/m055-focus-crop.jpg) 与 [m056河谷坡口](../../assets/roads/m056-focus-crop.jpg)。ST街段是普通Object，VL轨道另接；m056有普通桥体而BridgeBuilder数为0，不能按统计宣称无桥。ST06的m056 #843为Z=0/alignToTerrain=true，高程210–235.45，是局部贴地小样，不能全图+1或强制缺省false。

道路骨架优先两三个长轴与横向次街；转弯服务于地形、河岸或街块边界，不每栋房屋绕一个 S 弯。直街可按用户指定 45° 奇数倍设置世界轴。一个路口只处理需要的连接，短折线重复制造紧弯容易导致破碎路缘。规划人行入口后再加路口设施、停车线、斑马线；道路标线类资源不能当路面。

硬边与自然边分开：砖地—路缘使用明确边线；草地—裸地可使用纹理细化。先做短段，在近景检查 45° 边缘是否有周期性三角；m056 近景有诊断渲染锯齿，m058 有大条纹，这些均不作为绘制方案。若边缘工具不能给出正确局部结果，暂停扩大并报告渲染/数据待核查，不能蒙上第二层随机贴图。

## 针对全市区战役图的可执行组合

将空地先按用途安排：住宅内院、医院前场、站前广场、仓储院、公园、街角绿地、堤岸步道或停车场。每一类只配符合用途的对象。城区密度由道路和街块决定，不由“总对象数达到多少”决定。主体民房禁止缩放与互穿；平行街排可用原生 L/U 形建筑形成院落，立面与街线一致。多个城区高度之间先留车辆斜坡或桥，完成连通再补挡墙与坡脚绿化。

建议先做一个“住宅＋商业前场”、一个“医院＋公园”、一个“站前＋铁路”、一个“码头＋仓库”的样板并截图核对，再把它们作为关系模板扩展；不复制原图的精确整组坐标。用户要求全部市区时，乡村木屋与农田不进入配置；外围可用城市公园、河岸工程和工业设施承接而不是空雪地。
