## 地区 → 场景 → 设施的设计树

- **城市 → 居住/办公街区**：车行道 → 连续人行带 → 建筑入口前场 → 后侧/侧向服务区 → 街树与街具。
- **城市 → 医院**：主要入口、车辆进出路、停车、周边绿化、过街位置形成一组，不是单放一个医院模型。
- **城市 → 车库/维修**：车道接门前工作面，停泊车辆靠边，作业区与步行面分开。
- **城市 → 公园/运动**：入口接人行道，内部有少量明确停留点。运动场的长轴和线条正确，旁边有净空，树冠不压进场地。
- **滨水 → 休闲岸线**：滨水步道与栏杆、景观节点、少量公共娱乐设施。货运吊机不直接插入游乐场中心。
- **港口 → 货运**：岸边卸货面 → 吊机 → 货箱/临时堆放 → 货运车道 → 仓库；有船位、有岸线接缝、有转向空间。
- **水系 → 桥**：两岸道路先对接，桥头同高并有进入空间；桥不是随意斜放在水里的地标。

## 港口、围合与路网候选

港口：`TH_harbor_crane01`、`TH_CargoContainer01/02/03/04/05/06`、`TH_JapanCrate01/02`。先放岸线和作业面，吊机吊臂朝装卸面/船位，货箱长轴沿物流车道；围栏 `TH_JapanFence01/02/03/04` 留出入口。不预设所有箱体能任意堆叠；用户禁止堆叠时保持单层。

岸线：东京 `TH_SeaWall01/02/03`，横滨 `TH_SeaWall04/05/06/07/08/09/12/13` 等候选。型号用途要逐个看形状，直边、凹角、凸角和桥头分别验证，端点拼合、顶沿同高、水侧朝外。不要把它们当有统一尺寸的墙砖。

道路：东京有 `HB_StreetSegment01/02/06/07/08/09/10/11/12`，横滨有 `ST_StreetSegment01/02/06/07/08/09/10/11`；现代港城可以混用来源前缀，但**一个连续车道优先同族、同宽、相容端点**。先做长直段与一个转角小样，记录入口和出口，不把每个转弯缩成小锯齿。

人行与标线候选：`HavanaSidewalk03/04`、`TokyoHarborTrim04`、`MykonosRoadTrim01`、`IslandFortressSidewalk01/02`、`HavanaWhiteLine01`、`HavanaParkingLines03`、`HeidelbergRoadMarkings01/04`。它们不都代表完整道路：先确认是真路面、路缘还是标线。路口再做斑马线与信号，停车入口要有可驶入的空隙。

桥 `HB_Bridge_02`、`HV_Bridge_01` 为横滨候选。桥两端、桥下水面、护栏和道路接头共同检查；模型看上去跨水并不能证明目标游戏寻路正确。

## 地表与完成步骤

| 功能 | 候选材料 | 使用要求 |
|---|---|---|
| 车行/作业面 | `Asphalt01/05`、`Pavement_TokyoHarbor01/02/03/04/09` | 按道路和港区功能分大形；同一车道色形连续 |
| 广场/前场 | `Pavement_CapeCod02`、相容铺装 | 规则边界接路缘，入口轴线清楚 |
| 绿化缓冲 | `Grass_CapeCod20`、`Grass_Heidelberg06/07`、`Grass_Hawaii01/06` | 在植被带或公园内，不能靠频率把街道也刷草 |
| 港区设备基座 | `SteelDeck01/02/03/04` 的适配型号 | 只在相应人工设施表面；港城不等于整张地图钢铁甲板 |

1. 定岸线、码头与桥，再定两条主要街道。
2. 分办公室/住宅、医院/车库、休闲、货运四类地块，每块至少有一个真实入口。
3. 用原比例建筑搭一小街区，通过后再扩展；建筑不缩放、不叠放。
4. 人行道、停车、路口信号与照路灯完成之后，加入街树、长椅、花坛和小服务点。
5. 纹理先大形、后局部边缘细化。硬铺装交界检查是否有三角齿；若仍有异常，保存重开、分离显示故障与数据故障，不把草模型遮挡当抗锯齿方案。
6. 白天/补光用于检查几何，原夜景用于检查氛围。夜景中无法辨别的小件要标记未确认，不能为照亮截图改动原图后误报为原版规范。
