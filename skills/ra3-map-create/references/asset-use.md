# 物体分类、用途与放置检查

先读当前地域与季节的风格页，再查本页。物体名称相似不表示尺寸、原点、正面或用途相同；同系列的01、02、03不能任意替换。全部观察候选在 [observed-assets.json](observed-assets.json)，不要把整份JSON塞进模型上下文。

## 先查少量明确候选

在 skill 所在目录运行：

```powershell
node scripts/lookup-assets.cjs --case m050 --category walls-gates-and-boundaries --limit 12
node scripts/lookup-assets.cjs --case m064 --category fortress-platform-and-edges --limit 12
node scripts/lookup-assets.cjs --case u015 --kind materials --search Grass --limit 12
node scripts/lookup-assets.cjs --search Hospital --limit 8
```

默认不把社区/MOD补充当官方场景候选，必要时显式加 `--include-supplements true`。工具返回实际出现的ID、出处、参考图与少量位置观察；它不证明当前MOD可用，也不证明模型解析正确。`currentCatalogEntryPresent`只代表制作索引时存在目录项；执行时仍查询当前 `ra3map_list_object_catalog` / 地表目录。`modelAppearanceVerified:false` 或 `visibleUseVerified:false` 不能被改写成已通过。

GameObject 目录缺项不能证明 Road 模板不存在。普通道路查询当前挂载的 `Road:<id>`；专用桥核对 `GameObject:<id>` 和 BridgeBuilder；地表贴图用地形绘制接口。模板声明、编译资源与贴图引用、编辑器外观、目标 WB/游戏运行结果分别核对，见 [游戏兼容验收](game-compatibility.md)。

## 场景实体归属

常驻民房、公共建筑、车辆、灯、街具、树木与灌木，先确认地图已有 Civilian 玩家/队伍，通常使用 `PlyrCivilian/teamPlyrCivilian`，沿已核查样例和常驻用途选择。用户确认 R5 Preview的Civilian装饰保留正常，已撤回物件缺失猜测；不能据此断言所有Neutral装饰都会消失，也不能以地编显示或 owner 字符串合法代替加载后的保留检查。矿脉、可占领科技、敌军与任务对象仍按其玩法设置，不能把所有 Neutral 对象批量改为 Civilian。已有图修改归属必须符合用户范围；先核查任务引用再改。

本轮后续原生Save A/B定位的是地表混合格式：零尾输入11731有效引用全部失效，纯尾修复输入的同批引用全部语义保留。这不是实体归属或模型缺失的证据；R6游戏边缘仍待实测，详见 [游戏兼容验收](game-compatibility.md)。

## 一个地块的最低关系

先定用途，再安排：建筑正面 → 前场/入口 → 人行连接 → 街道；建筑后面 → 后院/服务区 → 后勤通路。墙服务院界，灯服务路线，椅子服务停留区，垃圾桶服务使用节点，树与灌木服务明确绿带。每个对象必须能回答“为什么在这里、朝向哪里、与谁配合”。

密集不等于无空地。街块内部可有公园、后院、堆场、停车、修建场地或破损空地；用连通地表和符合用途的小组细节表达它，避免没有原因的大白面。若用户要求全市区，不再用成片林地与孤立村舍代替街区。

先实际看一个原生尺寸建筑小样、一处围墙入口、一对灯和一个转角；把可见问题修好后再复制。记录成功小样的型号、角度、端点与高程，不把“统计出现过”当成可直接执行的摆放模板。
