# 道路连接、转弯与中立设施

按 [地区与季节](style-index.md) 选道路，结合对应完整分区与近景看接头、路边物件和院落关系。旧 [风格候选](style-design.md) 和 [3D 图册](../assets/styles/gallery.html) 保留作补充，目录标签有冲突时以新风格页和实际画面为准。全量数据与精确坐标统计用于找案例，不自动判定画面正确。

## 道路系统与路线骨架

道路、铁路、桥头或木质铺装先读 [道路制作与小样](road-construction.md)。该页给出两点Road、StreetSegment普通Object、rail、BridgeBuilder、普通桥体/平台的区别，地区季节候选、实测型号尺寸/本地轴、Z与贴地三态、当前MCP示例和目标原生检查；这里保留路线与中立设施的共同关系。

先按用途写主路线端点和必要转折。竞技例如基地→中央→扩张；城市战役例如车站→中心广场→医院/住宅/码头，货运服务路线另接仓储。每次转弯应服务于山脊、水湾、建筑群或交叉口。用少量长段组织骨架，开阔处不加入没有用途的S弯；自然山地保留真实坡口和必要转折，不硬拉成穿山直线。

车行面、人行路、白线、停车线、路缘、铁路和海墙分别组织。乡村可直接用土路Road，不强制铺城市StreetSegment。每型号模型先看真实长轴、端面、宽度与纹理方向；两点Road相邻段复用精确端点，T字支路接垂足拆点后重读下标。轨道/桥需各自构件、道床、桥头坡道和可达空间，材质小径/跨水线不能代替真实通行。

统计用 `ra3map_list_objects(exact:true,includeProps:true)`。仅连续同类型且起终点位匹配的记录成对分类：Road 2/4、BridgeBuilder 16/32；普通街段/轨道/桥体Object另算。

`scripts/analyze-composition.cjs` 的0.25世界单位端点桶只是近似诊断，不是引擎接头容差。未配对、预览条带或新版UI连接提示不能自动归罪于地图作者。用户R7和R8游戏反馈均仍异常，新图NRoad/Kremlin异型混连也有风险；不得把拆段或全图清紧弯/Join当通用修复。UI提示非阻断，不禁止混连、不自动清flags；按 [道路异常隔离与验收](road-construction.md#6-目标原生异常与提示的边界) 核全路宽地形、局部端点和目标WB/game。

## 矿脉与其他中立设施

先定资源服务哪个基地或扩张、所在高程层、陆矿/海矿类型和可达通路，再确定朝向与精确落点。矿脉要与矿厂停靠/采矿方向配合；通过实际模型和游戏检查矿车出入，不仅看贴图圆圈。其周围留足矿厂展开、矿车和进攻通路，树石围栏不要侵占这些空间。

本轮 80 图识别到的 **1328 个 OreNode 朝向均落在 45°+90°整数倍**，这是可采用的原版候选朝向，而不是所有中立物体都必须锁四方向。位置对齐的是旋转后的占地角点，不是把中心 x/y 各取 10 或 30 的倍数。普通 MCP 放置命令不会自动替你执行 UI 吸附；要读取当前 `ra3map_object_place_info` 的几何/标志，并确认目标版本的网格原点和尺度。

占地半轴 hx/hy、角度 a 对应角点偏移 `dx=cos(a)hx−sin(a)hy`、`dy=sin(a)hx+cos(a)hy`。角点转入网格坐标后以 30 为间隔吸附，再减回偏移得到中心。圆柱/球和 BOX 的两轴处理不同，原版的负坐标取整及方向边界也有专门规则；不要只照一个简化公式重写引擎。

**样本网格相位不能忽略。** 当前目录中的矿位有明确的随可玩高度变化的相位；分析器分别报告世界原点角点残差和观测到的地图高度相位残差。多数样本在后者下吻合，但还有不吻合的点，可能涉及几何、缩放、旧资源或地图变换。两种残差都只是诊断；不能把旧图全部“校正”到原点，也不能把该相位直接宣称为已确认的通用原版规格。已有图保留精确矿位；新图使用目标版本实际显示与提交的吸附结果，摆一个测试矿和矿厂，保存重开并确认游戏内采矿。未完成该验证时在交付中写明，不隐藏不确定性。

观测站、油井、医院等先通过当前目录查真实类型，再按用途放置：中心地标应有进入空间和两侧合理可达性；扩张附近的中立设施不能挡矿厂；民房可驻守性按当前类型核查。设置正确中立玩家/队伍，z 默认相对地面为 0，避免用绝对地形高度作为对象 z。
