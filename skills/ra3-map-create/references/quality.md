# 验收与边界

## 数据检查

- 统一服务成功打开，解析没有 incomplete/resynced/有损字符串；保存返回 Ok 与 VerifiedRoundTrip，关闭重开成功。这只是 Core 往返；原始保留的块可能没有专用结构验证，不能代替目标 WorldBuilder 或游戏验收。
- 支援元数据与用途一致。新图显式生成 map.xml，已有 XML 显式同步；竞技图检查出生点连续唯一、玩家/队伍与 XML 人数，并使用 Map_MP 同名文件夹/同名 .map、IsMultiplayer=true。战役检查任务需要的玩家、路径、触发与单人元数据，不自动增添遭遇战出生和经济；仅写 isScenarioMultiplayer 不能代替 XML 验证。
- 高程和通行标志按逐格读取，不能把自动降采样值当成完整地图。水域按多边形覆盖和水位判断；只读第一片水域的水位会误判多湖泊。
- 所有用途均检查真实建筑占地、入口、基础高度和道路通行，不能只看中心点。需要基地与经济的地图再检查展开区、可建造标志、矿厂空间和接驳；没有这些要求的城市战役不凭空补矿。
- 竞技图检查各方经济、可达路径和扩张风险；战役检查任务目标、行动路线与场景逻辑。样本中的首矿直线距离不是通用经济规则，更不是所有地图的验收条件。
- corridorRadius 表示保守的通路半径：r=3 需要至少 7 格带宽。简单网格检查覆盖地形标志、水位、建筑占地，不能模拟桥梁、所有道具碰撞、单位寻路和采矿接驳。
- 纹理可解析和目录有物体不等于模型百分之百正确。重点物体需看 3D 或模型预览；缺资源时换已验证资源或明确需要哪个 MOD。
- 地形结构按 terrain-design 检查。高差统计应排除海床和岸边带，检查坡道逐格坡度与成片区域的连接。大平地比例高、低高差或少山不是自动失败理由；必须有与设计相符的区域、边界和连接。
- 支援文件检查实际回执与存在，不能把 `status:error` 当生成成功。128 TGA 与地图同名，额外游戏选图预览需要显式生成 `_art.tga`。预览失败时保留地图，不为取巧生成预览而毁掉地形层级。

## 画面检查

按 visual-review 看图并保留修正前后图片。纯 agent-kit 的俯视渲染不能证明模型解析、水面或近景材质没有问题，report 的 visualReviewed 初始为 false，只有实际看图后才在独立验收记录中说明通过项。

## 游戏实测

按 [游戏兼容验收](game-compatibility.md) 分开检查目标 WB 稳定加载和实际游戏启动。新建格式、道路/桥梁或大批资产先验证小样，避免把只能由 Core 重开的缺陷扩到全图。游戏按用途检查选图/加载、常驻装饰保留、道路与桥梁通行、模型和贴图；用户要求基地展开时，战役或场景也检查陆地/水面 MCV，不只把它列为竞技项。竞技图再检查采矿、扩张、海路和 AI，战役再检查任务触发、胜负与演出。未制作任务脚本的场景只能称战役场景草稿，不能称已完成可玩战役。使用当前用户的游戏或平台，不擅自改游戏安装/注入调试器。已有 ra3map_game_status/game_exec 能连接时可用，否则记录未检查及具体手动项目。

gameTested 永远不会由数据验证脚本、工具数量、Core 或 WB 成功状态自动设为 true。只有实际运行地图的游戏证据才能标记；其值不能覆盖装饰、MCV、路径或脚本的单项未通过/未检查结果。竞技平衡需多局对战/作者评审，单次开局也不代表平衡。

## 适用范围

自动生成器目前是双人自然海岸/雪地台地岛草稿，陆路验证器默认所有矿点为陆矿。海矿、纯海战、桥梁/平台和复杂河流按实际玩法分别检查，不能擅自拿默认陆路结果判死这些设计。局部美化只增加装饰并证明源文件与原有对象未变，不认证整图经济和寻路。8 人、MOD 任务和城市生成需要额外案例和检验；把同系列改版分到同一案例组，避免拿近重复图当独立泛化成绩。

当前版本测试的是流程执行、脚本负例与视觉案例，不是独立模型能力排行榜。记录工具调用数/执行时间；不声称模型费用降低多少或一次就能生成发布级地图。
