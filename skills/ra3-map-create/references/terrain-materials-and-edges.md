# 地表绘制与纹理边缘细化

v5 的 [起义逐区图册](../assets/uprising/gallery.html) 与 [美化规则](uprising-beautification.md) 增加雪港、干燥峡谷、滨海院落、火山和台地的材质位置关系。[新案例数据](uprising-cases.json) 同时记录两个混合引用、露出地表候选与未知索引；未知不进入配方，区域底纹数量包含海床/隐藏底座，必须结合可见画面。

先打开 [图册](../assets/beautification/gallery.html) 的材质完成局部、[热带材质诊断](../assets/beautification/m001-materials.png) 或 [冬季城市材质诊断](../assets/beautification/m053-materials.png)。诊断色只是纹理类别编号，真实颜色和混合宽度看同位置 3D。

## 哪里刷什么：先确定地表用途

把地表分成区域底纹、次级变化与有原因的细节。区域边界应解释地形或使用方式：草地的干湿、林下阴影、坡脚碎石、岸边沙泥、房屋铺装、车道磨损、雪地清理和路边积雪。低频的大区域先成形，再用少量相关辅纹打破重复，最后处理入口和边缘。不要用细小随机色斑填满所有空地。

| 地表位置 | 绘制关系 | 样本候选与证据 |
|---|---|---|
| 热带草台地 | 主草面延续到坡道；干土局部接道路/裸露地，岩纹集中于实际岩坡与坡脚 | m001 露出陆地以 `Grass_Yucatan02` 为主，伴随 04..09 与 `Rock_Yucatan01`；陆地占比与海床分别统计 |
| 冬季开放地 | 连续雪底纹，相关雪纹做积雪变化；道路、院落和林缘的脏雪/裸土各自成片 | m053 `Snow_Solvang01` 与 `Snow_Iceland04`，真实混合配对最常见于两者之间 |
| 冬季城市 | 雪面与使用中的铺装相接；院落、建筑前沿和街道共同组织，不能只在每栋房下刷孤立色块 | m053 的 `Pavement_Vlad02` 与雪面经常相混；m054 还用 Vlad01/03/04/05/06 等铺装；号码不能当作材质用途标签 |
| 日本庭园 | 草地、砾石、裸土和入口铺面形成连通功能区；边饰单独画 | m068 `Grass_Gibraltar2`、`Grass_Heidelberg01`、`Gravel_Yucatan01`、`Dirt_Yucatan06` 等存在真实混合关系 |
| 中欧街区 | 庭院/绿带延续相关草面，街道与广场铺装成连续面 | m071 `Grass_Heidelberg02` 与 01/06/07；`Pavement_Heidel01`、`Pavement_Heidelberg10`，道路边饰独立 |
| 度假与滨海城市 | 城市铺装、修整草地、沙滩与岩岸分别组织，岸线连续而不等宽 | m070 `Pave_Cannes01`、草纹与岸边沙纹；m074 Havana 铺装、泥岸与热带草纹 |
| 地中海干土 | 同色系干土形成大片变化，住宅院落/绿化是有边界的小区域 | m079 `Dirt_Mykonos01/03/05/04` 的配对大量出现；白墙院落与道路用不同空间表达 |
| 火山地貌 | 裸岩、火山土与普通草台地分区；从火山向外过渡，不能全岛铺同一岩纹 | m080 `Cliff_Easter01`、`Dirt_Easter*`、CapeCod/Easter 草纹；看实际火山与台地位置 |

这些是候选关系，不是全图配额。样本中 `Sand_Cannes*`、`Dirt_*` 等高占比可能来自海床。`dryPercent` 已按水域和高程排除淹没采样格，仍可能包含被建筑底座遮住的材质；需要局部可见画面确认。陌生编号必须查看预览或试刷，不能因为叫 Pavement 就推断它一定是车道。不要把 m053 陡坡上的某些铺装当作推荐坡材。

## 绘制顺序和尺度

先做地形、水位、坡道和区域边界，再定主底纹。沿地貌、街区、林缘和河岸画连续辅纹，保留连通的主面；道路入口、建筑门前、转角和坡脚最后细化。道路贴图及路沿记录与地表铺装不是同一层：路面必须用道路工具连接，油漆桶填满地表不能替代道路节点。

自然边界使用可读的大弧线和少量凹凸，保持相邻区域的理由与连续性；草/土/沙边缘可渐变。铺装停车区、围墙基部或路沿可能需要清晰几何边界；通过窄边饰或局部细化过渡，不把每条硬边都抹软。三材质相遇处先确定哪一种延续、哪一种收尾，避免一个格同时挤入过多混合层。

## 本地工具的实际操作

在侧栏选择 **纹理边缘细化**，从模式中选择：

- **自动向外扩散（点一格）**：选中目标材质区域内部的格，向邻材质生成过渡。范围 0 表示整个连通区；局部修改时指定范围，避免影响已有成熟边界。
- **自动向内扩散（点一格）**：另一套边界处理，不是向外操作的撤销。先在局部试做，检查区域轮廓与回执；不要将其当作固定“收缩一格”。
- **混合单个边（拖一条）**：2D 中从来源格拖到相邻目标格；3D 中用两次点击指定起终点。未指定纹理时用来源格的材质；面板选择具体纹理时使用该纹理。方向有意义，反向操作不等价。

当前数据由底纹和两个混合引用构成，一格的混合容量有限。大范围自动处理会按顺序占用混合位，可能改变已有细节；先预演指定矩形，检查实际改动数，再应用和对照画面。不要每次绘制之后无条件“整图处理”，也不要清空整图混合去修一小处。

## 新地编平滑，目标 WB/游戏仍硬切时

先确认是同一保存版本、同一交界和同一运行资源。新地编预览可根据方向/角权重呈现平滑过渡，不能证明目标原生程序接受了全部盘上格式。UI 和 MCP 共用公共边缘生成底座；出现差异不能直接归为 Skill 漏调用 Auto Edge Out，也不要通过反复全图混合掩盖原因。

当前新生成的 BlendInfo 尾部格式标记固定为 `0x7ADA0000`，去重包含此值，避免新记录复用零标记旧记录。普通打开/保存仍保留已有值。先用 `ra3map_get_blend_format` 只读分类；需要修复旧零标记时使用显式 `ra3map_repair_blend_format`，然后另存、关闭、fresh 重开检查。它只修实际块版本27中可识别的零标记，保留异常/未知记录，不改变材质、方向、两层引用或区域轮廓。参数、回执和重开顺序见 [连接与操作](operations.md#混合格式检查与另存重开)。

尾标记符合格式不等于游戏过渡已经平滑；它不能修复相反来源、三材质冲突或错误区域形状。用户在物版 WB 同位置重刷同一种材质后 Auto Edge Out 成功，是具体局部证据；重刷会重建混合状态，不能单独证明成功仅来自尾标记。先保留对照并限定最小重绘范围，重新检查两层引用和附近成熟边界，再验证实际游戏。案例与单字段对照边界见 [游戏兼容验收](game-compatibility.md)。

后续纯尾字段原生Save A/B已把格式问题定位到该物版路径：原零尾A的11731个有效混合全部变占位/清除，修复B的11731个已用引用材料/phase、六flags、customEdge与Extra逐项保留，底纹270400格材料/phase不变。B仅去掉6460条未引用描述并重编号，不能把正常压缩误判为丢失。此结论是原生读取/保存保留结果；R6实际游戏边缘尚待反馈，不将它替代游戏同位置看图。

## MCP 用法与检查

工具坐标含 border：`cell = world / 10 + border`。先列当前挂载的纹理，再查询目标区域；缺少逐格工具的旧版需升级地图服务，不用原始解析器代替。

```json
{"tool":"ra3map_get_terrain_cells","arguments":{"handle":"<validated-handle>","x0":17,"y0":17,"x1":47,"y1":47,"step":1,"includeBlends":true,"maxCells":1000}}
```

`textureRows` 索引 `textures`，两层混合的 0 表示未引用，其他值用返回的 `blendInfo.id` 查次材质与方向标志。该表只含实际采样引用，ID 不一定连续；不能用数组下标当 ID，也不能把有引用数当可见过渡面积。

```json
{"tool":"ra3map_paint_texture","arguments":{"handle":"<validated-handle>","cx":32,"cy":32,"width":20,"textureName":"Dirt_Yucatan03","strokeId":"yard-soil-1"}}
{"tool":"ra3map_auto_edge_out","arguments":{"handle":"<validated-handle>","cx":25,"cy":25,"radius":20}}
{"tool":"ra3map_blend_edge","arguments":{"handle":"<validated-handle>","fromX":22,"fromY":25,"toX":21,"toY":25}}
```

这些坐标只是图册实验，任务地图要按实际边界取点。`width` 为官方格边长，`points` 可补全长笔画；同一笔用同一 `strokeId`，新笔换 ID。跨多个区域分批执行并检查回执，避免留下断开的点状笔迹。

45°硬边优先在一小段上选定主从，仅对一个来源材质执行一次局部 `ra3map_auto_edge_out`，看同机位再扩展；不要把相邻两种材质都反向处理同一交界，也不要把长对角混合替换成最近邻的逐格正交单边。[高对比实际实验](terrain-edge-lab.md) 中，双向 `ra3map_auto_edge_out_all` 会产生相反覆盖和三角齿，不能作为默认消锯齿步骤。批量矩形处理只有在具体版本、边界小样证明可用后才使用，并先 `dryRun:true`；单边工具用于明确的局部接头。基础绘制改变区域形状，混合改变接触区表现，分别验收。

独立实验的 [未处理](../assets/beautification/edge-painted.jpg)、[单边](../assets/beautification/edge-single.jpg)、[自动处理](../assets/beautification/edge-auto.jpg) 使用同机位：自动向外改了 84 格，单边改了 1 格，撤销及保存重开通过。这证明操作范围与数据留存，不证明方形地块是好的自然构图。

完成后看游戏视角、近俯视和坡脚低角度，检查草/土、雪/铺装、岩/草、岸/水以及三材质交点。最后按 step=1 复查问题局部并保存重开。step=2 的统计不能证明两采样格之间没有过渡，也不能直接统计所有硬缝。
