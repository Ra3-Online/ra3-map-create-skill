# 1v1 地形：层级、路线与可用平地

自然岛图、起伏地形或用户反馈“大平地”时，先看本页和 [地形案例图册](../assets/terrain/gallery.html)。实际打开一张高度/阻挡诊断图与对应 3D 图。高差有意义，平地也有意义；判断它们怎样安排基地、扩张与进攻路线。

## 从这次样本学到什么

重新逐格读取了 1v1 目录的 9 个文件，包含 feasel1 的同图编辑版，按 8 个案例组理解。原图哈希未变。统计只取可玩范围，陆地按实际水多边形及水位判断；内部陆地还去掉岸边四格带。图中 P10–P90 是陆地中间 80% 的高度范围，不能拿整图最大/最小值代替：海床很深，不代表岛上有山。

| 样本 | 实测结构与内部陆地 P10–P90 | 可迁移的设计决定 |
|---|---|---|
| black1b / m001 | 210–284.98；中央另有约 355 的内层台地，外围也有台地和坡道 | 基地低地留空，外围绕路与上中央台地的坡道构成不同进攻选择；地表道路沿地貌转折 |
| feasel1 / m002、编辑版 m003 | 210–280；离散高地、低地通道、湾口与平台物件 | 避免完整圆环；同一低地中也可由分散高地和海湾划出路线。平台物件上的出生区需另查，不能只按高度图判断 |
| feasel4 / m004 | 280–350；立体平台中央高层、两方平台及水域凹口 | 学多层平台和连接关系；这是工业平台场景，不能把其装饰语言当作自然山地 |
| feasel5 / m005 | 210–280；沿岸台地与深入主岛的水湾、实际桥梁 | 水道切入陆地，坡道和桥口决定进出位置；平整区仍占大部分，轮廓已有层次 |
| feasel6 / m006 | 210–280；内部阻挡约 8.39%，大段弯曲高地包围基地周边低地 | 山脊围出区域，留缺口和连接段；出生地与近矿通常共层，扩张可以换层 |
| feasel7 / m007 | 210–210；内部阻挡 0%，分岛、海路和桥梁承载结构 | 平坦也可以成立。用岛的分离关系、岸线凹凸、海上扩张和登陆点组织玩法，不能为提高“起伏分”乱造山 |
| feasel8 / m008 | 215.60–281.01；内部阻挡约 29.34%，曲折且彼此分离的山脊 | 让宽平地贴邻局部强地标；山脊切分路线，不能把整岛做成均匀波纹 |
| PROMO_Feasel1 / m009 | 210–310；约 73% 内部陆地落在 260–265，仍有海湾、边缘高地和城市结构 | 大平地占比高不必然失败；看平地边界、主岛轮廓和地标是否产生明确空间关系 |

这些是参考图的结构观察，不是地图平衡认证。部分矿位在水域，平台/桥梁可提供高度图以外的可用表面。不能直接照搬出生点、海矿数量、桥梁或直线距离。结构数据见 [terrain-cases.json](terrain-cases.json)。

## 地形先写成结构图

在放装饰前，写一份简短的地形规格。各区包含：用途、范围、目标高程、可走/不可走边界、与相邻区域的连接方式、矿厂或地标留白。重点是关系，例如：

> 两方基地与近矿共用平整台地；前方宽坡道通往中央低地，侧坡道通往沿岸扩张；两段弯曲高地分隔中央与侧路；上高地扩张另有坡道；中央观测站位于宽阔鞍部；两个海湾给海路和登陆点留空间。

这个例子适合有陆路的双人主岛。分岛海战应换成“出生岛→海路→扩张岛/登陆点”的结构；无海图用河谷、山脊或街区承担分区。**不要把所有任务套成同一岛形或同一组坐标。**

先安排大片可用平地和主要台地/山脊，再开连接口，最后加细起伏、岸坡和碎石。高地既可作为可上去的扩张，也可作为不可通行的分隔；在规格中说明用途。噪声仅修饰表面，不能代替地貌分区。用贴图画出的道路不会限制单位走捷径。

## “略有起伏”仍可有结构

根据视图比例和用户要求选高差，不机械复刻样本的 70。少量低台地、浅谷、宽鞍部和局部岩岸，也能产生可读层次。保持基地和近矿局部平整，把变化放在分区边界、路线连接和扩张侧翼。若用户明确要平坦地形，采用分岛/水道/街区等结构；不强迫加山。

当前脚本的 `gentle` 是一份可改造的草稿：水位 200、沿岸低地约 220、基地约 240、高地扩张约 270、中央鞍部约 250。`standard` 把基地/高地改为 250/290。它们是本配方的选值，不是通用合格线。原始平岛反例、此配方测试结果与仍待美化的地方都保存在图册中。

## 坡道怎样落地

坡道要连接上下两个平面，两端留平缓接头，宽度按军队通行需求规划。`corridorRadius=3` 的检查需要至少 7 格完整带宽；画面上看似宽敞，也可能被岩石、矿点占地、侧壁或一格台阶切断。

格距为 10。高差 ΔH、水平长度 L 格的平均坡度为 `atan(ΔH / (10×L))`。平滑插值的局部坡度可能高于平均值，因此依据逐格相邻高差核查坡道接头、侧缘和材质交界。不要把地图上的 `passability=0` 当成任意陡坡都能通行；地形坡度和存储标志分别检查，桥梁/平台再按实际游戏验证。

台地与岩壁边界应明确，坡道只在计划的连接位置渐变。全图平滑会消掉山脊，全图硬台阶则会制造阻塞。平整基地、矿厂和民房时，只局部保留各自所在层的高程，别把所有路线和资源预留区压到同一个高度。

## 用去装饰的画面验收结构

在材质和装饰前，用俯视高程/阻挡图、基地至扩张的剖面、低角度坡道图回答：

- 地貌能否被描述为不同的区域？各区平地是否够用？
- 高地、岩壁或水湾在哪里把路线分开？从哪几个开口连接？
- 两方近矿是否便于展开？扩张的路径长度、坡道与海上暴露面是否符合设计？
- 关键坡道实际连接吗？地标/矿厂放入后是否还保留预定通路宽度？

如果回答仍是“一块大平地上画两条路”，先修地形。不要靠增树、换贴图或把几个小土包抬高来完成验收。但对于 m007 这类分岛图，水道和登陆点就是可接受的结构证据，不要求内部岩壁。

运行 [地形诊断脚本](recipes.md#地形诊断) 可取得实际高程层次、成片平地、阻挡、地形通路及出生点/近矿高度。诊断值用于定位问题，不自动打审美分或判竞技平衡。最终仍需看 3D；当前草稿的岸线台阶、规则台地轮廓和缺少岩壁装饰都需要按任务继续处理。
