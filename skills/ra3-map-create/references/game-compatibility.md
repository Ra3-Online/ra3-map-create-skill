# 游戏兼容验收

制作道路/桥梁小样、新建或修复地图格式、批量放置常驻实体以及最终交付时读本页。目标是区分内部数据正确、目标 WorldBuilder 能稳定加载，以及实际游戏行为。已有用户失败反馈的项目记为未通过，不能降写成“待确认”或被其他通过项覆盖。

## 先定运行环境和入口

记录游戏/MOD、WorldBuilder 版本、资源挂载、目标地图文件与版本或哈希，以及预期入口：遭遇战列表、单人任务启动，或仅场景交付。单人任务不普遍要求两个出生点；本轮一处出生点、单人元数据的场景不能据此保证会进入遭遇战列表。用户需要遭遇战验证时，可在获准的新测试副本中配置双位和相应 Map_MP/XML，保留原任务图。

## 执行检查表

每项只填 **通过 / 未通过 / 未检查 / 不适用**，并写证据文件或实际测试说明。按用途选择适用项；没有经济需求的城市不补矿，没有任务脚本的场景不称完整可玩战役。

| 项目 | 具体操作和证据 | 不能据此判通过 |
|---|---|---|
| Core 往返 | 统一服务打开；解析完整；Ok/VerifiedRoundTrip；关闭重开并核对对象、地形和目标结构 | 原版 WB、游戏列表、模型表现或部署行为 |
| 目标 WB 稳定加载 | 用相同引擎/资源打开确切文件，确认主窗标题；观察主窗后是否退出、报错或卡住，记录观察窗口和结果；有能力时取得实际视口图 | 只收到启动 PID、短暂出现主窗；Core 重开；没有像素证据时的视觉质量 |
| 游戏列表/启动和加载 | 在预期入口实际找到或按任务入口启动该文件，并确认加载到地图；XML/支援文件与地图匹配 | 文件存在、XML 成功、IsMultiplayer 字段、游戏进程启动或 WB 成功 |
| 常驻装饰保留 | 游戏加载后检查代表性民房、车辆、灯、家具与绿化；对照 owner 和截图 | 地编中物体可见、对象数量、owner 合法字符串 |
| 地表边缘表现 | 保存后 fresh 重开，在目标 WB 和游戏检查同位置的雪/铺装、斜向边、凹角与三材质交点；记录版本、资源和机位 | 新地编预览平滑、混合引用非零、规范尾标记、Core 接缝连续性统计 |
| 陆地 MCV | 用户要求时，用具体阵营 MCV 在计划展开区实际展开；核查真实 footprint、坡度与周围碰撞物 | 平地、buildability 字段名或位值、静态通行检查 |
| 水面 MCV | 用户要求时，验证该单位支持水上部署，并在目标水位/水域实际展开；留够展开空间 | 海面平坦、全图一片水、陆地展开通过 |
| 路径/脚本 | 实际单位穿过关键路口、坡道、桥与门；任务触发、胜负和演出按已制作范围运行 | 路/桥外观、道路节点成对、脚本树存在、保守网格可达 |

`gameTested` 初始为 false，仅实际运行该地图的游戏证据能改为 true；它表示已做过游戏实测，不代表表中全部项目通过。Skill 静态检查、调用数量、Core/WB 状态和截图脚本执行次数都不能赋 true。WB 稳定但截图超时，分别记 WB 已观察稳定、视觉未检查；游戏未运行仍为 false。

## 格式与已有地图的边界

- `ra3map_get_new_map_compatibility` 可用时，检查 MP 六槽的专用结构、Library 对应最终玩家，以及登记模式。原始保留块可往返不代表专用结构有效。
- `ra3map_repair_new_map_skeleton` 是显式、可撤销、不保存的操作，仅修本项目可识别的旧零块。规范块无改动，未知非零拒绝；不应挂在普通打开/保存上重建用户 MP 配置、非空 Library 或历史 AssetList。
- 新建/显式修复会话的登记使用真实资源类别；Road 与桥梁 GameObject 不混用。正常历史地图的登记不完整不自动判坏，不为了“全登记”改普通图。
- 需要修复时先确认符合支持条件，保留副本；执行后读回目标结构，检查 undo/redo，再保存关闭重开。格式通过仍须做本页相应原版验收。

### 混合尾标记和单字段对照

`ra3map_get_blend_format` 只读区分规范、可修复零、异常零与未知非零；`ra3map_repair_blend_format` 显式修实际 BlendTileData 版本27的已识别零尾标记。它不重算方向、不改格引用、不自动保存；未知/异常保留并计数，其他版本不改。工具只有可选 handle，完整 schema 示例与回执含义在 [连接与操作](operations.md#混合格式检查与另存重开)。UI/MCP共用公共底座，不把显示差异直接写成某入口漏调用工具。

官方 RA3 样例和独立 [OpenSAGE 解析/写入源码](https://github.com/OpenSAGE/OpenSAGE/blob/master/src/OpenSage.Game/Data/Map/BlendDescription.cs)支持尾 u32 常量 `0x7ADA0000`。本轮受控原生打开+Save A/B进一步定位：只改此尾字段，目标物版 WB保存后的已用混合由全部失效变为全部语义保留。这已是该原生路径对格式的直接验证，不能再仅表述为样例相关性。实际游戏画面仍需单独验证；原生保存行为不是 EA游戏渲染分支或游戏视觉通过的证据。

做单字段 A/B 时：原件保持 SHA不变，副本另存后关闭、fresh重开，核对所有 chunk 名称/顺序/版本、字符串池、HeightMap、纹理表、底纹、两层引用、cliff、所有位平面，以及对象顺序/type/坐标/角度/roadOption/全部 props/propTypes、players/teams/scripts/WorldInfo。只允许合格18字节记录的 offset14..17 变为小端 `00 00 DA 7A`，其前14字节与全部其他 payload原样。读取原始块必须在重开的会话，编辑中 `CopyRawBytes` 仍是读入旧 payload。经统一服务导出后的 payload可逐字节对账，不另写原始地图解析器。

方便选图而另改 mapName、出生点、faction、registry或支持XML的版本，必须单列这些变化，不能冒称单字段。原生/游戏对照保持资源挂载、画质/profile、同地点与机位；记录实际运行文件与哈希。若仍硬切，边缘项目仍未通过，不能以格式、加载或其它玩法项目覆盖。

原生 WB Save会重排纹理/混合表、重编号引用并重写多个 chunk，**原生保存后的输出不要求仍是单字段字节差异**。单字段断言用于送入原生程序之前的 A/B；保存后用 fresh Core按坐标比较材料名称与子块相位，并解析每个引用对应的 secondary材料/phase、六方向字节、customEdge、Extra，核查引用是否变占位或被清除。底纹也按材料/phase比较，不把 tile raw数或 blend ID变化直接判成视觉损失。原生处理前后若有其它对象/metadata变化，单列记录，不能称整图逐字节不变。

## 资源类别和运行组合

普通道路应解析当前挂载的 `Road:<id>`；专用桥应解析 `GameObject:<id>` 与 BridgeBuilder；TerrainTexture 用地表工具。GameObject-only 索引缺项、SDK 空 Art XML 或模型渲染成功，分别都不能证明 Road 模板缺失或运行安全。对声明、编译资源及其引用、放置参数、目标运行结果分开记证据。

先保存一个真实尺度小样，在目标版本验证道路类型、长度、共端点、转角/join 标志和桥参数，再扩大制作。发生 WB 退出时，保留文件，在获准副本按地形/混合、普通实体、道路/桥梁逐层隔离，再按类型或具体组合缩小。不要因一个组合失败把全部道路、所有类似贴图或所有 priority 同值模板判无效，也不要没有依据地改已有图。

## 常驻实体与展开标志

常驻民房、公共建筑、车辆、路灯、街具和绿化通常用地图已有 `PlyrCivilian/teamPlyrCivilian`，沿已核查的样例和常驻用途选择。本轮用户确认 R5 Preview的Civilian装饰保留正常；不要将此前物件缺失猜测继续写成Neutral必消失的证据。矿脉、可占领科技与任务对象按玩法归属，不全局转换所有 Neutral。已有任务引用需保留，游戏加载后实际核查保留情况。

当前 RA3 buildability bool 极性仍待原版标记样例或实际 MCV 验证。沿新建默认/官方样本恢复位值 0，是数据修正的候选依据，不是游戏展开通过。不要把全图 true 当作“可建造”；已有图按编辑范围保留，遇到部署失败先核查位平面、坡度、占地、资源/道路附近限制与单位本身能力。可行的独立极性验证是原版 WB 在两块已知坐标分别标 Buildable/Not Buildable，另存获准副本后统一 Core 读回，再验证实际部署；不能借 Generals 或其它游戏的字段解释证明 RA3。

草稿生成器保留 Core 的新建位默认，不全图覆写 true。`validate-map.cjs` 的 `passed` 仅表示 `validationScope` 中的静态检查；完整模式报告全图及展开候选区 0/1 分布，不用未知极性判 0 不可建或 1 可建。`buildabilityPolarity` 为 `unverified`，`gameplayGate` 的陆地/水面部署与路径/脚本为 `not_tested`，`gameTested` 为 false。局部美化模式没有重新读取全图时，分布明确记 `not_read`，不补造统计。

## 已知案例：斯大林格勒 2026-10-09

此案例记录一个具体环境，不能当跨版本通用禁用表。

- R3/R4 在 New World Builder v16 中出现主窗后退出。隔离的地形+混合、1690 个普通实体样本观察约 20 秒稳定；道路层退出。
- 八种道路和两种桥的单类型小样中，只有 `KremlinSnowyTracks01` 的四段 0xC2/0xC4、长度约 290/2800 的组合退出。它确实有 EA SDK Road 定义及挂载编译 Road/Texture 资源，不是不存在或分类错误；触发机制未完全归因。在相同环境验证新组合前，临时不复用该组合。
- R5 的道路修正仅删除对应八个节点，保留 88 个 `VL_Rail01`。R5 单人版（校验前缀 `2dcd`）、R5 Preview 测试副本（`30ef`）、R2 Compat（`ed3c`）分别在 New World Builder v16 中，同一次加载每隔约 5 秒检查，共六个样本、约 30 秒均运行且没有错误对话框；记为这些确切版本的 WB 稳定加载观察通过，不能推为所有节点组合或版本都安全。
- 早期工具尝试全屏/窗口游戏启动，SKY 的 FrameArrived 捕获超时，reset 重试仍失败；当时三版本的游戏项都记未检查。**后续用户已实际进入 R5 Preview（30ef）游戏，并澄清物件没有丢失、一切正常，仅贴图边缘有问题。** 该版本的游戏启动/加载与用户报告的装饰保留通过，`gameTested=true`；不把先前“部分物件缺失”猜测留作已知缺陷。R5单人版、R2 Compat没有因此自动取得游戏通过，陆地/水面 MCV与路径/脚本仍未检查。
- 同位置新地编预览的雪/铺砖过渡平滑，但用户游戏与物版 WB显示硬台阶，故 R5 Preview地表边缘未通过。用户在物版 WB重刷同一种材质后再做 Auto Edge Out成功，说明该环境能产生可见过渡；重刷和重建记录同时发生，尚不能把结果单独归因某个尾字段，也不能判 Skill漏调用工具。
- 新地编已修新生成记录的尾标记，增加只读检查与显式旧零标记修复。R6的纯格式对照从30ef派生：7410条记录只改 offset14..17，经 fresh重开与统一服务导出对账，4,137,729字节解压 payload仅14,820字节不同，字符串池与其它数据全部逐字节相同，原件SHA不变。用于游戏选择的 R6 EdgeTest在此基础上另改mapName，并生成相应支持文件；它与纯单字段副本分别记录。**R6实际游戏边缘结果尚待反馈，不能声称症状已修。**
- 在同一 New World Builder v16物版环境，复制原零标记A（30ef）和纯尾修复B（f419）分别打开、执行原生 Save，再用fresh Core对账。A另存为b1e2后，原11731个有效alpha引用全部失效：11554个变占位引用、177个清除。B另存为c26f后，11731个引用逐格的材料名称/phase、六flags、customEdge与Extra全部差异为0；全部270400格的底纹材料/phase也不变。B混合表7410→950，恰好删除6460条未引用记录并重编号，950条已用记录语义全部保留。**因此已定位本次物版WB读取/保存路径不保留原零尾格式，尾字段修复恢复其原生语义保留。** 原生输出重写多个chunk，不声称其仍逐字节单字段；此次没有运行游戏，R6游戏边缘仍待实测。
- buildability 恢复 0 沿默认/样本，不记陆地或水面 MCV 通过。单人原图保留一处任务出生点，遭遇战列表及实际任务启动分别待其入口验证。

案例证据名称：`r3review-road-classification.md`（SDK/编译分类）、`native-r5-result.json` 与 `native-repaired-result-20261009.json`（WB 观察）、`urban-buildability-evidence.md`（极性限制）、用户R5 Preview游戏/物版同位置对照与澄清、`blend-ab-20261009/validation.json`（纯尾字段对账与命名副本）、同目录 `native-save-ab-result.json` 和 `r3review-native-ab-summary.json`（原生Save与引用语义对账）、`blend-format-code-repair-validation.json`（格式/事务回归）；它们属于制作项目证据，不是 Skill 安装包依赖。新任务仍需当前环境的小样和实际验收。
